# PEF 公共语法规范

本文件定义编译器的输出语言：`P + ΔV → J` 及三条错误处理规则的精确含义。所有编译报告必须遵守本规范。

## 1. 三元组

```
P + ΔV → J
```

- **P（主体 Subject）**：一个带时间戳的交接方。它漂移、老化、可以被锚定。没有时间戳的「主体」不是 P，是要被拆解的 `P?`。
- **ΔV（变量 Variable）**：过手的东西。从产生岸看是**内容**；从接收岸看是**势能差**。同一 ΔV，两侧两个名字，不矛盾。
- **J（结果 Result）**：接收侧落地的东西。J 是落地的，不是生成的；「生成」是产生侧的动词，不能出现在结果位。

> 这个三元组不是对宇宙的发现。它是任何交接的最小语法：**有东西发出，有东西传递，有东西落地。** 真正新的是挂在它身上的三条错误处理规则。

## 2. 三条错误处理规则

### 规则一：不可自证（No Self-Certification）

被审计方不能同时是审计依据。

- 模型说自己对齐——不算，要外部评测。
- 体系说自己是终极答案——不算，自证陷阱。
- 「我悟了，所以我说的对」——不算，`P?` 加软锚。

**反例判定**：如果偏差由被审计方自报，审计对象与审计基准合二为一，审计结构上失败。

### 规则二：必须外部锚定（External Anchoring Mandatory）

进入结构的每个断言，必须有一个可被独立复现的锚。

- π 的位数可重算（硬锚）。
- kT·ln2 在教科书（硬锚）。
- 塔科马大桥的 129 天在档案（硬锚）。
- 「你做得对」只存在于说话者心里（软锚，不进结构）。

**软锚处理**：软锚可以作为钩子、比喻、文学文本存在，但不得作为结构证据。

### 规则三：允许局部失败（Local Failure Permitted）

系统不要求永远正确。它要求：失败被记录、可审计、可局部失效而不拖垮整体。

- 勘误表：只追加不涂改。
- 版本管理：原文保留，修正另记。
- 死亡条款：体系要能预写自己的失败方式。

## 3. 证据三档

| 层 | 内容 | 进结构条件 |
|---|---|---|
| 框架内事实 | 本体系术语与推导 | 可，标注来源 |
| 物理与历史事实 | 教科书可查 | 可，必须可查 |
| 工程观察 | 经验数据 | 仅线索，不作定论 |

## 4. 术语表

| 术语 | 定义 | 常见误用 |
|---|---|---|
| P | 带时间戳的主体 | 当作「永恒自我」 |
| ΔV | 过手的变量（内容/势能差） | 当作「预先存在的完整物」 |
| J | 接收侧落地结果 | 写成「生成」 |
| 硬锚 | 可独立复现 | 把软锚当硬锚 |
| 软锚 | 只存在于说话者心里 | 放进结构当证据 |
| 勘误 | 原断言→判定→修正，只追加 | 涂改原文 |
| 源 | 无参考、先于时间、不可观测 | 给它命名/谓语/视角 |

## 5. 对「源」的三条禁令（从《源，与它的名字》继承）

1. **不要给它下谓语**。说「源是恒常的」是把变量层的属性投影到源上。
2. **不要给它视角**。无参考即无「对它而言」。
3. **不要给它命名**。一个「它」已经是命名，命名即投影。

对源只有三种合法语法：否定的（不是什么）、指示的（指向哪里）、带距离的近似（像什么、在什么限度内）。
